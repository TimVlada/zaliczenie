# CONTRIBUTING

## Zasady współpracy w projekcie Zoo Online

Dziękujemy za chęć dołączenia do projektu Zoo Online.
Poniżej znajdują się zasady współpracy, których należy przestrzegać podczas pracy nad projektem.

## Tworzenie branchy

Każda nowa funkcjonalność lub poprawka powinna być tworzona w osobnym branchu.

Schemat nazewnictwa branchy:

* feature/nazwa-zadania
* fix/nazwa-poprawki
* bugfix/nazwa-błędu

Przykłady:

* feature/penguin-page
* feature/honey-badger-page
* fix/navbar-style

## Zasady commitów

Commity powinny mieć krótkie, czytelne i konkretne nazwy.

Schemat:

* feat: dodanie nowej funkcji
* fix: poprawka błędu
* style: zmiany wizualne
* docs: zmiany w dokumentacji

Przykłady:

* feat: add penguin page
* fix: repair menu navigation
* style: improve page layout

## Sposób komunikacji

Komunikacja w projekcie odbywa się za pomocą:

* GitHub Issues
* GitHub Pull Requests
* Trello

Każda większa zmiana powinna zostać wcześniej zgłoszona i omówiona z zespołem.

## Dodatkowe zasady

* Przed wysłaniem zmian należy sprawdzić poprawność działania strony
* Kod powinien być czytelny i uporządkowany
* Należy dbać o spójność projektu
* Każda zmiana powinna zostać opisana
